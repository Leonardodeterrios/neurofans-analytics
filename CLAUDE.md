Партнёрский трекер переходов с соревнованием двух команд и «Муай-тай ареной».
Владелец — Лёня (не программист). Общаться по-русски, коротко, давать готовые

## Как это работает
- Партнёры ставят в био ссылки вида `https://go.ai-creators.ru/t/<метка>` (Threads) или `/v/<метка>` (видео: Shorts/Reels/TikTok); `/go/<метка>` и `/go?source=` — без канала.
- Клик пишется в SQLite и редиректит в бота: `t.me/<BOT_USERNAME>?start=<метка>-<id клика в base36>` (старый вид `<метка>__<id>` тоже принимается).
- Воронка бота живёт в **PuzzleBot** (@AccessGrantedGuide_bot). Мы бота не поллим: токен нужен только для `sendMessage` (уведомления), иначе конфликт с PuzzleBot.
- PuzzleBot в команде /start делает «Отправить запрос» (GET):
  `/bot/start?p={{start_payload}}&uid={{USER_ID_TEXT}}&key=<INGEST_TOKEN>`.
- Команды: метки `leo01…leo50` → команда A («Команда Лёни», 🌊, #19d3c5), `kate01…kate50` → команда B («Команда Кати», 🌺, #ff4f8b). Префиксы/имена/цвета в `.env`.

## Правила подсчёта (не ломать без согласования)
- Удар (+1) = уникальный человек на партнёра за раунд. Человек = cookie `nf_vid`, иначе хэш IP+User-Agent.
- Один человек засчитывается максимум `MAX_PARTNERS_PER_VISITOR` (3) партнёрам за раунд; с IP — максимум `MAX_HITS_PER_IP` (100: за одним IP операторов сидит много людей).
- **Фильтр сканеров (с 22.11.2026, согласовано с Лёней):** удар засчитывается только если (1) клик с телефона или из приложения (`MOBILE_UA`: Mobile/Android/iPhone/iPad/Instagram/Barcelona/FBAN/TikTok/YouTube…; `REQUIRE_MOBILE=1`) и (2) IP не из сети дата-центра/хостинга (`HOSTING_ORG` по названию сети из DB-IP ASN Lite `data/geo-asn.mmdb`, качается сама раз в 35 дней; `BLOCK_HOSTING=1`; Cloudflare/Akamai Technologies/Fastly НЕ блокируем — это iCloud Private Relay). Плюс (3) строка браузера не поддельная (`forged_ua`: версия iOS с нулевым третьим числом вроде `26_3_0`, или Safari, чья `Version/` не совпадает с версией iOS — `16_6_1 … Version/16.5`; при этом с iOS 26 настоящий Safari пишет `OS 18_6 … Version/26.0` — это НЕ подделка) и (4) с одной подсети /24 (IPv6 /48) — не больше `MAX_HITS_PER_NET` (10) ударов за раунд (прокси-сканеры идут блоками адресов). Такие клики пишутся с `scored=0` и `why` = `desktop`/`hosting`/`forged` (лимиты — без why), редирект тот же. 22.11.2026 после всех фильтров из ~10 800 кликов сканеров осталось ~16 ударов. Причина: новые домены попадают в журналы сертификатов, и за сутки сканеры (UCloud, DigitalOcean, Hetzner, leakix…) набили ~1400 «ударов». `rescore_all()` пересчитывает `scored` у всех кликов и стартов по текущим правилам (клики не удаляются); один раз выполняется сам после появления ASN-базы (`meta.rescore_v2` — при смене правил поднять номер в коде, и пересчёт пройдёт сам при следующем запуске), вручную — `/admin/rescore?token=<DASHBOARD_TOKEN>`. Свои тест-клики с компьютера тоже не считаются — проверять с телефона.
- Боты/превью-краулеры/скрипты (`BOT_UA`) не пишутся, но получают **тот же** редирект, что и люди. Встроенные браузеры Instagram/Threads/TikTok/Facebook/YouTube — люди (покрыто тестами).
- IP: перед приложением стоит caddy и кладёт адрес соединения в `X-Real-IP`; приложение верит этому заголовку только от внутреннего (private) адреса, т.е. от caddy. `CF-Connecting-IP` — только при `TRUST_CF=1` (сейчас 0). Иначе IP можно подделать.
- Уникальность Telegram-аккаунта для апперкота — на всё время, не на раунд: апперкот = новый человек в боте, иначе одних и тех же людей можно «прогонять» каждый день.
- Апперкот (+`START_POWER`=3) = новый Telegram-аккаунт пришёл через **засчитанный** клик этого партнёра — или через клик, отсеянный только как `desktop` (компьютер: не удар, но дошедший до бота человек — живой; согласовано с Лёней 22.11.2026). Клики `hosting`/`forged` апперкот не дают. Один старт на клик. «Голые» t.me-ссылки и `direct` не считаются. Доходимость ≤ 100% (`_conv` обрезает: апперкот теперь бывает без удара).
- Действия в боте (кнопки PuzzleBot → `GET /bot/action?act=<код>&uid={{USER_ID_TEXT}}&key=<INGEST_TOKEN>`): examples +8 (с 21.11.2026, раньше +2; очки пишутся в строку `actions.points`, старые записи не пересчитываются), guide +3, prompts +3, sim +4, channel +4, reviews +5, site +8, program +10, intent +12, checkout +20 (`ACTIONS` в app.py; последние три — ближе к покупке, с 22.11.2026), **paid +1000 — настоящая оплата клуба** (22.11.2026, по просьбе Лёни): только вебхуком Tribute `POST /tribute/webhook` (подпись `trbt-signature` = HMAC-SHA256 тела на `TRIBUTE_API_KEY`; события new_subscription/new_digital_product/new_donation, продление не считается; `TRIBUTE_CLUB_IDS` — id товара/подписки клуба, пусто = любая покупка; возврат (`*refund*`) снимает очки), через переходник/кнопку не получить (нет в `ACT_LINKS`). Копия вебхука в фоне уходит кабинету (`TRIBUTE_FORWARD`, по умолчанию `http://lab:8090/api/tribute/webhook` — Pro учеников). Админам — уведомление «💰 ОПЛАТА КЛУБА» всегда. На арене — эффект `jackpot`: суперприём + робот + дрон, золотые взрывы по всей арене, монетный дождь и плашка `#jack` «+1000 КЛУБ ОПЛАЧЕН». Очки получает партнёр, чей **засчитанный** старт у этого tg_uid; uid без засчитанного старта — тихо игнорируется (200, `uid_not_attributed`); пара (tg_uid, act) — один раз за всё время (UNIQUE в таблице `actions`). Ответ всегда 200, кроме неверного ключа (403).
- **Кнопки-ссылки бота → переходник `/a/<код>`** (22.11.2026): все 7 кнопок воронки в PuzzleBot — ссылки (мини-приложения ai-creators.ru: examples/guide/prompts/sim/site; в браузере: channel/reviews), PuzzleBot при нажатии ничего не шлёт. Поэтому в кнопке стоит `https://go.ai-creators.ru/a/<код>?u={{USER_ID_TEXT}}`: страница отправляет POST на тот же адрес и сразу (≤1,5 с) открывает настоящую страницу из `ACT_LINKS` (адреса только из кода/`.env ACT_LINKS=код=https://…`, не из ссылки — не открытый редирект). Человек: подписанный `tgWebAppData` мини-приложения (`tg_webapp_uid`, HMAC на `BOT_TOKEN`, не старше суток) — надёжно; иначе `?u=` из ссылки (кнопки «в браузере»; засчитывается только uid с засчитанным стартом). Дальше обычный `record_action`. Кнопки дальше по воронке тоже идут через переходник: «Запустить симулятор» → sim, «Смотреть галерею» (та же страница /primery) → examples, «Изучить систему на сайте»/«Перейти на сайт проекта» → site, «Почитать внутрянку в ТГ-канале» → channel, «Посмотреть все отзывы» → reviews, «Посмотреть программу клуба» → program (ai-creators.ru/#tariff), «Хочу такие же результаты»/«Забрать систему обучения» → intent (#tariff), «Оплатить доступ»/«Вступить в клуб» → checkout (Tribute `t.me/tribute/app?startapp=s13fW`). Одна страница = один код, чтобы человек не приносил очки дважды за одно.
- Ачивки (`BADGES` в app.py, считаются в `_get_stats`): first_blood, champ, belt, ko, sniper, hundred + combo (5 ударов за 10 мин в раунде), heavy (2+ действия по +8 за всё время), globe (5+ городов за раунд), funnel (4+ разных действий в боте), rush (сила раунда ≥10 и ≥2× прошлого), marathon (сила в 5 раундах подряд), night (удар 00:00–05:00 по `SUMMARY_TZ`). Для рейтинга партнёру отдаются `heavy`, `heavy_today`, `cities_today`, `hot` (удары за 15 мин).
- **Уведомления и выгрузка в таблицу — только в фоне** (`bg()` → очередь + поток `bg-notify`; `notify_all`, `push_sheet`): с сервера в РФ api.telegram.org отвечает медленно, и синхронная отправка админам (таймаут 10 с × число админов) держала редирект в бота ~30 с. Ничего сетевого внутри обработки клика/старта/действия не делать.
- Сила = удары + 3 × апперкоты + очки действий в боте. Раунд — «от гонга до гонга» (`DAILY_SUMMARY_TIME`, по умолчанию 21:00 Asia/Bangkok); в гонг итоги уходят в Telegram всем `ADMIN_CHAT_ID` (через запятую).
